# LP demo usability and accessibility check

Scope: the new `/liquidity` page, reviewed against the existing Blossom design
system, Nielsen heuristics and relevant WCAG 2.2 AA behaviors on 2026-09-13.
This is a focused implementation review, not a complete conformance audit.

## Verified

- Built page reads both real local sponsorships (five USDC each, USDC/EURC valuation)
  from the rehearsed deployment and labels estimates as projected voting weight.
- Disconnected state explains how to find positions; transaction actions are gated.
- Deadline is displayed with a semantic time element. Details distinguish sampled
  market prices from an independent oracle and explain stale-price behavior.
- At a 320-pixel viewport the document fits its available width, including the full
  pool ID when details are expanded. Desktop and narrow layouts were visually checked.
- A valuation disclosure opens with Enter, retains focus and shows a visible focus
  outline. Native summary elements expose expanded/collapsed state.
- NFT lookup has a visible label and an associated descriptive hint. New sponsorship
  fields indicate that they are required and associate valuation hints with inputs.
- Signing, confirmation, success and error messages use the existing live status/alert
  pattern. A pending hash is retained for receipt checking after reload.
- Registration calls PositionManager once with the selected campaign; a wrong wallet
  network fails before simulation/signing. Ineligible positions offer no claim button.
  These transaction guards and presentation states pass component/unit tests.

## Corrections made during review

Added wallet-step announcements and hint associations, exposed the accrual deadline,
gave the route its own title, and replaced the low-level Q96 price display with an
explanation of the valuation source's practical limits.

## Remaining live checks

No injected user wallet was connected during browser review. Signing, wallet network
switching and real Arkiv uploads need the funded-wallet walkthrough in the runbook.
The local tests exercise transaction code and existing Arkiv UI flows with controlled
wallet/transports, not the user's wallet extension. No screen-reader session or
automated axe audit was run; contrast inherits existing shared tokens and was not
independently remeasured in this change.

The first Vite development load encountered a stale dynamic-module fetch during
dependency optimization. The final production build rendered correctly and was used
for browser review. The existing Swarm connection timed out during the final preview
and displayed its retry notice. LP reads still loaded both sponsorships correctly;
the LP demo does not require a Swarm upload.
